# КАРАВАЙ — менеджерское превью 0.3

По заданию от 13.10.2026 менеджерский кабинет содержит пользователей, покупателей и получателей. Заказы полностью исключены из интерфейса: меню, обзор, счётчики, фильтры, таблицы, вкладки, карточки и журнал. Предыдущие версии сохраняются в истории Site. Технические сущности `payers` и `payer` сохраняют имена; подписи интерфейса — «Покупатель».

Приватный Site и автономный HTML остаются тестовым превью. Они не выполняют сетевых вызовов и не подключены к VM, PocketBase, КИС или почте. Демо нельзя выдавать за установленный рабочий кабинет. Модуль сохранён в отдельной ветке GitHub по поручению от 13.10.2026; исходники клиентского кабинета, база VM и её настройки этим добавлением не меняются.

Приватное превью: https://karavay-manager-demo.just-owl-1110.chatgpt.site. Приватность Site не является ограничением доступа к исходникам в GitHub.

## Файлы

- `src/` — исходники интерфейса, локальная тестовая модель, стили и фирменный логотип.
- `standalone/Karavay-Manager-Demo-v0.3.html` — готовый автономный HTML, который можно открыть в браузере без сервера.
- `scripts/build-standalone.cjs` — сборка из `src/` без сторонних зависимостей.
- `scripts/Collect-Karavay-Manager-Source.ps1` — выгрузка четырёх действующих обработчиков с VM, без изменения сервера.
- `tests/` — проверки модели, действий интерфейса и автономного файла.
- `dist/` — локальный результат сборки для статического размещения; в Git не сохраняется.

## Изменения

- Обзор ориентирован на три действия: добавить пользователя, покупателя и получателя.
- У покупателя две вкладки: получатели и пользователи.
- Пользователь может иметь нескольких покупателей, все или отдельные точки у каждого.
- Получатель добавляется выбором существующей карточки КИС, согласно ответу пользователя. В превью представлены явно тестовые карточки; новые точки в КИС не создаются.
- Выбор карточки проверяет совпадение покупателя, числовой ID и отсутствие дубля. Данные берутся из карточки; поля запроса не подменяют её название. Перепривязка точки к другому покупателю запрещена.
- Создание и редактирование пользователей/покупателей, включение/отключение, восстановление, журнал и защита несохранённых правок сохранены.
- Старые записи журнала о заказах скрываются без сброса остальных тестовых изменений. Исторические функции заказов в локальной модели не вызываются интерфейсом и не являются серверным API.

## Рекомендуемое рабочее размещение

На той же VM и том же origin PocketBase:

- `/` — кабинет клиента;
- `/manager/` — кабинет менеджера, отдельная папка `pb_public/manager`;
- `/_/` — существующая админка PocketBase;
- `/service/manager/*` — предлагаемые защищённые серверные маршруты управления.

Первый внутренний адрес менеджера: `http://192.168.25.98:8090/manager/`. Это предлагаемый путь, он ещё не установлен. Отдельный порт, экземпляр PocketBase и база не нужны. Внешний HTTPS/домен — отдельный последующий этап; текущая работа не публикует персональные данные в Sites.

## Основа рабочего подключения и текущий блокер

При подготовке превью использован `KARAVAY_HANDOFF_2026-10-11_MAIN_3.7.1.md`: по этому документу на основной VM установлен PB 0.40.3 с моделью 2.0 и HTML 3.7.1. Основные коллекции `users`, `payers`, `rights`; роль — `role_code`; права получателей — `scope` и `kis_client_id`. Старая связь `rights.client` сохранена переходно и не должна использоваться как новый источник назначения. Это сведения из передачи состояния, не независимая проверка VM при сохранении в GitHub. Сам локальный прототип сохраняет тестовую модель `roles/clients` со связями `rights.client`; перед рабочим подключением её нужно заменить адаптером актуального серверного контракта.

Проверен актуальный GitHub: AGENTS.md, PROJECT_CONTEXT.md, readmegpt.md, POCKETBASE_ACCESS_MODEL.md, POCKETBASE_KIS_GATEWAY.md. Документация main остаётся на контрольной точке 08.10.2026 и не содержит актуального установленного комплекта hooks. Старые архивы нельзя считать действующим серверным исходником.

Существующие `/service/context` и `/service/clients` обеспечивают пользовательское чтение. Подтверждённых менеджерских маршрутов создания пользователей/покупателей и назначения прав нет; Write API основных коллекций закрыты. Требуется отдельный серверный слой с ограничением роли и назначенной области. Открывать коллекции для всех или помещать superuser-токен в браузер нельзя. Получатели выбираются через PocketBase из КИС; браузер не обращается к внутреннему upstream.

Следующее необходимое входное данное — четыре актуальных файла `/opt/pocketbase/pb_hooks/karavay-*.pb.js`. `scripts/Collect-Karavay-Manager-Source.ps1` копирует только эти четыре файла по SSH в Windows Downloads и собирает ZIP. Сервер не изменяется, база и настройки не выгружаются. Пользователь вводит SSH-пароль в терминале. По полученному коду будет подготовлен совместимый серверный модуль и рабочий frontend `/manager/`, затем проверен установочный пакет.

Матрица полномочий должна ограничивать `manager` его покупателями, `viewer` запрещать вход в менеджерский API, исключать повышение собственной роли и назначение чужих точек. Подключение нового покупателя по КИС ID требует проверенного правила назначения области; одного введённого ID недостаточно для предоставления доступа. Сброс пароля требует отдельной проверки SMTP.

## Проверка и сборка

Нужен Node.js 20 или новее. Установка пакетов не требуется. Из корня репозитория:

```sh
npm --prefix manager-demo run check
```

Сборка отдельно: `npm --prefix manager-demo run build`. После сборки можно открыть `manager-demo/dist/index.html` или автономный HTML. Исходники редактируются в `src/`; сборщик обновляет `dist/` и файл в `standalone/`.

40 проверок пройдены. Проверены удаление заказов со всех поверхностей и недоступность прежних действий, выбор карточки КИС/дубли/область, создание и редактирование, назначения, восстановление, локальное сохранение, защита правок и автономный файл. Интерфейсные проверки используют заглушки DOM. Визуальный прогон в браузере и проверки живых PocketBase/КИС не выполнялись.

Статическое размещение — `dist`, существующий owner-private Site. Автономный файл — `standalone/Karavay-Manager-Demo-v0.3.html`; идентичная копия создаётся в `dist/`. Сборщик встраивает стили, логотип и JavaScript. Реальная установка в `pb_public/manager/` будет отдельным пакетом после получения обработчиков и проверки серверного управления.

## Выгрузка исходников VM для следующего этапа

Скачать `scripts/Collect-Karavay-Manager-Source.ps1` в Windows «Загрузки» и выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Collect-Karavay-Manager-Source.ps1"
```

Скрипт копирует `karavay-context.pb.js`, `karavay-clients.pb.js`, `karavay-catalog.pb.js`, `karavay-orders.pb.js` из `/opt/pocketbase/pb_hooks/` через `scp` и создаёт ZIP в «Загрузках». Обработчик заказов выгружается для проверки совместимости действующего шлюза; интерфейс менеджера заказов не содержит. При ошибке копирования ZIP не создаётся. База и пароли не выгружаются, PocketBase не перезапускается. Скрипт должен запускаться с компьютера, имеющего доступ к VM по SSH; в среде подготовки он на VM не выполнялся.
