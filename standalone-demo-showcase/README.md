# КАРАВАЙ — Demo Showcase 3.6.4

Самодостаточная HTML-версия личного кабинета для демонстрации полного интерфейса без подключения к КИС.

## Что подключено

- Авторизация, роли, права, плательщики и разрешённые получатели загружаются из реального PocketBase.
- Ассортимент, индивидуальные цены, заказы, документы и профиль формируются локальным демонстрационным слоем.
- Демо-слой включается только для плательщиков с кодом `DEMO-*`.
- Все маршруты `/api/v1/*` при активном демо-режиме обрабатываются внутри HTML и не уходят в КИС.
- Обычные пользователи и плательщики не переводятся в демо-режим.

## Два сценария

| Пользователь | Роль | Доступ |
|---|---|---|
| `tanushkova@gmail.com` | `manager` | Два плательщика, по два получателя; создание, корректировка и отмена демо-заказов |
| `mashuliaz@gmail.com` | `viewer` | Только `DEMO-P200 / DEMO-C201`; чтение без изменения заказов |

Пароли в репозитории и HTML не хранятся. Они задаются отдельно в PocketBase.

## Состав

- `base/` — проверенная рабочая версия 3.6.3, используемая как неизменяемая основа.
- `src/` — локальный адаптер демонстрационных бизнес-данных.
- `scripts/` — воспроизводимая сборка 3.6.4 (`build-demo-showcase.cjs`).
- `tests/` — сквозная DOM-проверка двух сценариев прав и всех основных разделов.
- `artifacts/` — готовый одиночный HTML-файл.

## Проверка

```bash
npm ci
npm run verify:showcase
```

Тест проверяет:

- цепочку `auth → role → rights → payer/client` на границе PocketBase;
- изоляцию двух плательщиков и ограничение viewer одним получателем;
- 111 товаров, ХБИ и замороженную продукцию;
- обзор, получателей, историю заказов, документы и профиль;
- создание, корректировку и отмену демо-заказа;
- запрет изменения заказов для viewer;
- отсутствие исходящих запросов `/api/v1/*` к КИС;
- очистку демо-контекста при выходе.
