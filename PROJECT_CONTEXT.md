# Контекст проекта

## Цель

Личный кабинет АО «КАРАВАЙ» для оформления и сопровождения заказов. Пользователь может работать с одним или несколькими покупателями/юрлицами; каждый покупатель содержит своих получателей/торговые точки. Целевой масштаб — около 600 точек.

## Версия 3.6 React + TypeScript + PocketBase user access

React + TypeScript является основной реализацией. Vanilla 3.2 остаётся исторической опорой, React 3.3 — функциональной базой миграции, React 3.5 — предыдущим каталогом `buyer → outlets`.

### Модель доступа

```text
users → user_buyers → buyers → outlets
```

- авторизуется только запись `users`;
- `user_buyers` задаёт many-to-many и роль `owner | manager | viewer`;
- прямой вход через `buyers` и `outlets` в HTML 3.6 удалён;
- один покупатель выбирается автоматически, несколько открывают экран выбора;
- переключатель юрлица повторно проверяет разрешённый каталог и загружает только его точки;
- F5 сначала обновляет сессию пользователя и связи, затем восстанавливает выбранного покупателя;
- токен и ID последнего покупателя хранятся только в `sessionStorage`;
- пароль, полные записи, КИС-креды и бизнес-данные не сохраняются в браузерное хранилище.

### Сохранено без регрессий

- React 18/Vite 8 и шесть разделов кабинета;
- desktop/mobile и мобильная закреплённая панель;
- каталог из 111 демонстрационных товаров и 7 категорий в явном mock-режиме;
- проверка заказа перед отправкой;
- единые ограничения минимального количества и кратности лотка;
- блокировка повторной отправки;
- подтверждение сброса несохранённых правок;
- immutable-обновления заказов;
- request gate для зависящих от состояния загрузок;
- recovery UI при ошибке начальной загрузки;
- unit, jsdom integration и Playwright E2E;
- production base `/react-test/`;
- TypeScript `strict`, без `any`, `@ts-ignore` и `@ts-nocheck`.

### Граница текущего этапа

- directory-режим получает пользователя, его активные связи, покупателей и активных получателей из PocketBase;
- некорректная схема, чужая relation и отказ API rules блокируют доступ fail-closed;
- при смене покупателя очищаются получатель, корзина, матрица, заказы, документы, правки и кэши;
- быстрое переключение защищено поколением запроса;
- матрица, заказы и документы честно помечены как не подключённые;
- mock API загружается только при явном `VITE_AUTH_MODE=mock` и `VITE_DATA_MODE=mock`;
- подготовлены standalone HTML, контракт, инструкция и миграция для ревью; VM этой веткой не меняется.

## Архитектурные решения

- Состояние: Context + reducer, без внешнего state manager.
- Навигация: внутренний route state; URL-маршрутизация пока не нужна.
- Бизнес-правила количества: `src/orderRules.ts`.
- Пользовательская сессия: `src/authApi.ts`; endpoint только `users/auth-with-password`.
- Каталог прав: `src/pocketBaseDirectoryApi.ts`; `buyerId` принимается только после проверки `UserDirectory`.
- Конкурентные загрузки: поколения запросов в `src/requestGate.ts` для покупателя, матрицы, последнего заказа и переключения юрлица.
- Доменные контракты: `src/types.ts`, включая `AuthenticatedUser`, `BuyerMembership`, `UserDirectory`, `SelectedBuyerContext`, `Buyer`, `Outlet`.
- Сборка: Vite 8, production base `/react-test/`; отдельный standalone для `pb_public`.
