# AGENTS.md

Перед работой прочитать `PROJECT_CONTEXT.md`, `readmegpt.md`,
`docs/POCKETBASE_ACCESS_MODEL.md` и `docs/POCKETBASE_KIS_GATEWAY.md`.
Для продолжения старого чата использовать `docs-project/CHAT_HANDOFF_2026-10-08.md`.

- Различать код main 3.5, раннюю React-ветку 3.6 и рабочий standalone 3.6.3.
  Актуальный контур — `users/roles/rights/payers/clients`, вход по email.
- Новые публичные бизнес-маршруты — `/service/*`; внутренний `/api/v1` КИС
  не раскрывать браузеру. Сервисный ключ КИС в выбранной схеме не используется.
- Custom routes PocketBase обязаны проверять активные user/role/right/payer/client;
  requireAuth и клиентский filter сами по себе не обеспечивают область доступа.
- Не применять старые миграции/коллекции поверх действующей VM без сверки схемы.
- Статус плана, пользовательское подтверждение и независимый тест не смешивать;
  демо-ответ не является успешной интеграцией КИС.

- Основная реализация находится в `src/`; редактировать исходники, не `dist/`.
- TypeScript работает в строгом режиме; не использовать `any`, `@ts-ignore` и `@ts-nocheck` для обхода типов.
- Сохранять модель покупатель → торговые точки и все шесть разделов кабинета.
- Правила количества держать едиными для каталога, проверки, корректировки и API.
- Не мутировать заказы и массивы позиций напрямую.
- Для запросов, зависящих от выбора пользователя, отсекать устаревшие ответы.
- Не подключать реальную авторизацию или production API без явного задания.
- После изменений запускать `npm run check`; при доступном Chromium — `npm run test:e2e`.
- Обновлять документацию вместе с изменениями поведения.
- Не коммитить секреты, `node_modules/` и `dist/`.
