# Памятка для продолжения проекта

Текущая основная версия — React 3.3. Vanilla 3.2 используется только как историческая опора в Git.

## Неизменные бизнес-ограничения

- Покупатель управляет одним или многими получателями/точками; модель должна выдерживать около 600 точек.
- В кабинете сохраняются шесть разделов: обзор, заказ, история, точки, документы, профиль.
- Заказ проходит явную проверку перед отправкой.
- Ограничения количества одинаковы в каталоге, окне проверки, корректировке и API: минимум SKU плюс кратность полного лотка для `lotOnly`.
- Ошибка API не должна уничтожать корзину или несохранённые правки.

## Технические ориентиры

- Не мутировать объекты заказов, позиций и кэшей; создавать новые структуры.
- Сверять асинхронный ответ с актуальным поколением запроса до изменения состояния.
- Держать бизнес-правила вне JSX в тестируемых функциях.
- `import.meta.env.BASE_URL` использовать для публичных ресурсов.
- Ошибки первоначальной загрузки должны иметь понятный экран восстановления.
- Пока не появится согласованный контракт, `src/mockApi.js` остаётся демонстрационным адаптером.

## Перед завершением любого этапа

1. Запустить `npm run check`.
2. При наличии Chromium запустить `npm run test:e2e` для desktop и mobile.
3. Проверить итоговый `dist/index.html`: ресурсы должны начинаться с `/react-test/`.
4. Обновить `README.md` и `PROJECT_CONTEXT.md`, если изменились адреса, архитектура или дорожная карта.

## Ближайший фокус

Следующий этап — не новые визуальные функции, а безопасное подключение реальной авторизации и API КИС через зафиксированный контракт, с контрактными тестами, наблюдаемостью и поэтапным включением.
