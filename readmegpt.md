# Памятка для продолжения проекта

Текущая рабочая версия — React 3.6 + TypeScript в ветке `feature/v3.6-user-multi-buyer-auth`. React 3.3 является функциональной базой миграции, 3.5 — предыдущей моделью PocketBase, Vanilla 3.2 — только исторической опорой.

## Неизменные бизнес-ограничения

- Авторизуется конкретный пользователь: `users → user_buyers → buyers → outlets`.
- Пользователь может иметь несколько покупателей, покупатель — нескольких пользователей.
- Покупатель содержит одного или многих получателей/точек; модель должна выдерживать около 600 точек.
- В кабинете сохраняются шесть разделов: обзор, заказ, история, точки, документы, профиль.
- Заказ проходит явную проверку перед отправкой.
- Ограничения количества одинаковы в каталоге, проверке, корректировке и API.
- Ошибка API не должна уничтожать корзину или несохранённые правки.

## Авторизация 3.6

- HTML вызывает только `/api/collections/users/auth-with-password` и `users/auth-refresh`.
- Прямой вход через `buyers`/`outlets` запрещён.
- `active` обязан быть `true`, `must_change_password` — `false`.
- Нет активных `user_buyers` → `NO_BUYER_ACCESS`.
- Один покупатель выбирается автоматически; несколько показывают отдельный экран.
- F5 повторно проверяет пользователя и связи до восстановления покупателя.
- Перед сменой юрлица очищаются все buyer-зависимые данные; при несохранённых данных требуется подтверждение.
- Токен и последний buyer ID хранятся только в `sessionStorage`; пароль не сохраняется.
- API rules обязаны независимо проверять активную связь; клиентский filter не является защитой.
- PocketBase/remote ошибки никогда не включают mock fallback.

## Технические ориентиры

- Не мутировать объекты заказов, позиций и кэшей.
- Сверять асинхронный ответ с актуальным поколением запроса.
- Держать бизнес-правила вне JSX в тестируемых функциях.
- `import.meta.env.BASE_URL` использовать для публичных ресурсов.
- Ошибки первоначальной загрузки должны иметь понятный recovery UI.
- TypeScript `strict: true`; не добавлять `any`, `@ts-ignore` или `@ts-nocheck`.
- Бизнес-данные КИС в directory-режиме показывать как не подключённые.

## Перед завершением этапа

1. Запустить `npm run typecheck` и unit/integration tests.
2. Запустить `npm run check` и standalone-сборку PocketBase.
3. При наличии Chromium запустить `npm run test:e2e` для desktop и mobile.
4. Запустить `npm audit`.
5. Проверить, что `dist/index.html` использует `/react-test/`, а standalone не содержит demo-профили или mock-товары.
6. Обновить `README.md`, `PROJECT_CONTEXT.md`, `docs/AUTH_CONTRACT.md` и инструкцию PocketBase.
