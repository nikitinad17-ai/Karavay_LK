# Получить настоящие названия покупателей и получателей с VM

16.10.2026 пользователь прислал скриншот успешного запуска: `KIS_VM_READ_OK`,
2527 покупателей; подтверждены ОАО «Каравай» ID 2 и АО «ПАЛЯНИЦА» ID 3 с
выборкой получателей. JSON скачался, TXT завершился `filename does not match request`.
Исправлено копирование: каждый отчёт скачивается отдельным вызовом scp,
без двух удалённых источников в одной команде. Повторное чтение КИС ради
получения уже созданного отчёта не требуется.

`Read-KIS-VM.py` выполняется на Ubuntu VM и обращается напрямую к
`http://serv15db:55580/api/v1`. Только GET: список покупателей, карточки
покупателей, их получатели и карточки получателей. Сервисный ключ и
администратор PocketBase не нужны.

По живым ответам выбираются два активных покупателя с подтверждёнными
получателями. НЕВА, ПРОМТЕХСБЫТ и IDs 300182/299271 исключены. Предпочтение
первому покупателю с несколькими точками. Для каждого выводится до двух
подтверждённых активных получателей: это выборка, не полный список всех точек.
Количество записей справочника получателей сохраняется отдельно.

Это предварительные кандидаты КИС. Область конкретного менеджера и связи PB
не проверяются и не изменяются; окончательные назначения выполняет отдельный
скрипт создания после сверки прав. Покупатели КИС, учётные записи PB, права,
заказы, настройки VM и опубликованные файлы не изменяются. На диске сохраняются
только сам скрипт и отчёты с ID/кодами/названиями; контактные данные не выгружаются.

## Запуск из Windows

Скачать `Karavay-KIS-VM-Read-20261016.ps1` в обычный Downloads и выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-KIS-VM-Read-20261016.ps1"
```

Скрипт загружает Python-файл на `lindevadmin@192.168.25.98`, запускает через
SSH, скачивает JSON/TXT и открывает текстовый результат. SSH использует текущий
способ входа компьютера и может спросить пароль; секреты не сохраняются.

Отчёты на компьютере:
`Downloads/Karavay-KIS-VM-20261016/Karavay-KIS-VM-20261016.json` и `.txt`.
При успехе: `KIS_VM_READ_OK`. При ошибке JSON всё равно скачивается для диагностики.
Повторный запуск обновляет эти отчёты.

Если уже открыт терминал VM, загрузить Python-файл и выполнить:

```bash
python3 ~/Karavay-Read-KIS-VM-20261016.py
```

Время ограничено тремя минутами, один запрос — 12 секундами; просматривается
до 100 других покупателей. Дополнительный `--scan-limit 500` увеличивает число
проверяемых покупателей, общий лимит времени сохраняется. Ошибки DNS,
соединения, HTTP и структуры ответа видны в отчёте. Прокси переменные окружения
не используются; перенаправления КИС не выполняются.

Проверка: отдельный локальный HTTP API, только GET, выбор/исключения,
неактивные и чужие получатели, старые десятичные числа КИС, HTTP/JSON ошибки,
сохранение ограниченного отчёта. Доступ к настоящей VM из среды разработки
не подтверждён. Имена fixture-данных не являются реальными компаниями КИС.

Сборка PS1: `python3 classic-release/quick-access/build-kis-read.py /path/to/output`.
