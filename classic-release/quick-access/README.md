# КАРАВАЙ — три тестовых аккаунта и вход кнопкой

Создаёт три отдельных аккаунта `demo.quick.point.<manager>@example.test`,
`demo.quick.buyer.<manager>@example.test`, `demo.quick.multi.<manager>@example.test`:

| Сценарий | Назначения |
| --- | --- |
| Один получатель (демо) | Один проверенный активный получатель одного покупателя |
| Все точки покупателя (демо) | Все активные получатели первого покупателя |
| Два покупателя (демо) | Все активные получатели двух разных покупателей |

Точные компании и получатели выбираются **при запуске по живым GET КИС**.
НЕВА, ПРОМТЕХСБЫТ и IDs 300182/299271 исключены. При выборе первого покупателя
предпочтение отдаётся нескольким активным точкам. Если у подходящих покупателей
только по одной точке, сценарий all остаётся доступом ко всем точкам этого покупателя.
Никаких локальных товаров, получателей или заказов не подставляется.

Скрипт использует активного менеджера; при нескольких попросит выбрать email.
Для существующего покупателя требуется полное активное право этого менеджера.
Покупатели вне его области пропускаются. Для ещё не зарегистрированного покупателя
создаётся связь PB с КИС и право all выбранному менеджеру, как в действующем
кабинете менеджера. Если поле `manager_owner` уже есть, новые пользователи
получают эту связь. Права других менеджеров не изменяются.

При первом запуске email и пароль superuser PB вводятся **в терминале**, один раз
для настройки. Если нужны несколько менеджеров, выбирается один. SSH может
запросить пароль подключения по текущим настройкам компьютера. Новые тестовые
пароли генерируются автоматически; ручной ввод и обязательная смена для этих
трёх аккаунтов не требуются. Обычный вход других пользователей не меняется.

## Запуск Windows

Скачайте `Karavay-Quick-Access-20261016.ps1` в обычный Downloads. Выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Quick-Access-20261016.ps1"
```

Скрипт сам распакует файлы в подпапку Downloads, загрузит настройщик на VM и
после `QUICK_USERS_READY` скачает в Downloads личный `Karavay-Test-Login.html`. В нём три
кнопки входа, фирменный клиент 3.8.0 и свежие данные PB/КИС. Можно переключаться
через меню «Тестовые пользователи» справа сверху. При F5 сессия обновляется
обычным auth-refresh; после выхода можно снова нажать кнопку. Файл открывать
в Chrome/Edge из сети, имеющей доступ к 192.168.25.98:8090.

Перед созданием скрипт проверяет checksum установленного клиента 3.8.0 и
разрешение CORS для локального HTML. При несовместимости останавливается.
Копия приложения сохраняет исходные проверки роли/прав/контекста/корзины,
добавляя приватную панель и фиксированный origin для относительных запросов.
CSP исходного клиента сохраняется с дополнительным хешем панели и конкретным
адресом PocketBase в connect-src. Никаких изменений pb_public, hooks или миграций.

## Повтор и приватность

- Приватный план: `~/.karavay-quick-users-20261016.json`, права 600. Содержит только
  сгенерированные тестовые пароли и назначения; пароль администратора не сохраняется.
- Личный HTML: `~/Karavay-Test-Login.html`, права 600, вне публичного каталога;
  затем копируется в вашу папку Downloads. Файл содержит вход в тестовые аккаунты:
  не загружать его в GitHub, Drive, Library или общую папку.
- Повторный запуск использует те же IDs, пароли и назначения. Дубликаты не создаёт,
  чужие аккаунты не перезаписывает, отключённый готовый аккаунт не включает.
  Частично созданные пользователи получают доступ только после проверки всех прав.
- После создания проверяются настоящий email-вход, роль owner, точное множество
  покупателей и изоляция одной точки через `/service/context` и `/service/clients`.
- Для отключения быстрого входа деактивируйте эти аккаунты обычным интерфейсом
  менеджера/PB и удалите личный HTML. Политика обычных учётных записей не меняется.
- КИС используется только для чтения. Создание заказа выполняется только явной
  кнопкой внутри кабинета и относится к рабочей КИС.

## Границы выпуска

База: `feature/client-classic-orders-3.8`, 5ce684c. Изменения только в
`classic-release/quick-access/` и проверках. Старый seeder не запускается;
переиспользуются только его функции чтения и сверки справочника КИС.
Менеджерские файлы, серверные контракты и клиентская сборка на VM не изменяются.
Новый запуск на рабочей VM требуется для создания аккаунтов. До вывода
`QUICK_USERS_READY` их создание на VM не считается подтверждённым.

Проверка 16.10.2026: `npm run check` (30 тестов), отдельная classic-сборка и CSP;
настоящий изолированный PB 0.40.3 с подменённой КИС: dry-run без записи,
прерывание/продолжение, три сценария, область менеджера, отсутствие сбросов и
дублей, изоляция, запрет включения отключённого аккаунта, приватность HTML.
Chromium 155: открытие личного файла через file://, вход кнопками во все три
сценария, F5/auth-refresh, выход, переключение и мобильная ширина панели.
Это локальные проверки на fixture-данных, не создание аккаунтов на рабочей VM.
