# Дата тестового входа и диагностика каталога — 27.10.2026

Скриншот владельца подтверждает реального покупателя/получателя и ошибку
`UPSTREAM_HTTP` при открытии прайса. Дата осталась 20.10.2026. Владелец отдельно
подтвердил: смена даты на актуальную также не загрузила каталог. Поэтому
старая дата не считается установленной причиной отказа прайса.

## Изменение даты

`karavay-test-access.js` раньше возвращал `preferredDate` из сохранённого
`buyers/history.proofs[0].day`. Это дата прежней проверки, которая устаревает.
Теперь metadata тестового входа возвращает завтра по Москве на момент запроса.
Сохранённые proof, пользователи, права, пароли и HTML не изменяются. Группа
продукции сохраняется из proof; без неё используется Group 1.

`catalog-date-check.py --apply-date` заменяет только этот helper при известном
SHA предыдущей версии. Перед заменой проверяются три активных тестовых входа
и отсутствие посторонних ожидающих миграций;
есть резервная копия, атомарная замена, перезапуск PB и проверка metadata.
При ошибке восстанавливается прежний helper. Бизнес-БД не откатывается и не
изменяется. Повтор уже применённой правки проверяет результат без перезапуска.
После запуска нужно перезагрузить страницу кабинета.

## Чтение каталога

Утилита входит через явно включённый тестовый multi-аккаунт, находит получателя
по переданному коду в его разрешённой области и проверяет принадлежность через
карточку КИС. Для настроенной точки используется точечный scoped GET; для
остальных — список с пагинацией. Латинская Y и кириллическая У нормализуются
для ввода кода, фактический код/имя/ID печатаются в результате. При неоднозначном
результате полного поиска выполнение останавливается.

Для сегодня/завтра по Москве, Group 1/0 выводятся:

- `CATALOG_RECIPIENT`: фактические покупатель, получатель, код и ID;
- `KIS_CATALOG_HTTP`, `KIS_MESSAGE`: статус и сообщение прямого запроса КИС;
- `GATEWAY_CATALOG_HTTP`: ответ публичного gateway для той же даты/группы.

В КИС разрешены только GET карточки и matrix выбранного получателя. В PB
единственный POST — passwordless login. Маршруты заказов запрещены явно.
PB-токен не передаётся в КИС, не сохраняется и не выводится; SQL stack не
выводится. Redirect запрещён. Ни цены, ни формат POST заказа не изменяются.
Операторская диагностика работает на VM; браузер продолжает использовать
только `/service/*`.

Запуск из Windows после сохранения PS1 в Downloads:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Catalog-Date-20261027.ps1" -ClientCode "Y42100"
```

Код получателя — аргумент оператора, не фиксированный ID/покупатель в коде.
`TEST_DATE_FIXED` подтверждает применение даты. `CATALOG_READ_COMPLETE`
подтверждает выполнение чтений, а не наличие исправного прайса.
Точная причина текущего `UPSTREAM_HTTP` станет известна после фактического
ответа VM; прежнюю ошибку цены нельзя автоматически считать новой причиной.

## Проверено

Node выполняет настоящий helper с фиксированными часами: московская полночь,
смена месяца/года, старые buyers/history proof и конфигурация без proof.
Python использует реальный локальный HTTP: разрешённая область/код/принадлежность,
четыре ошибки КИС и ответы gateway, запрет POST КИС/маршрутов заказов/redirect,
отсутствие токена и SQL details в выводе. Проверены фактическая атомарная замена
helper в изолированном каталоге, повтор, откат при ошибке/прерывании и сохранность
соседних файлов. `npm run check`: TypeScript, 34 теста и сборка проходят.
Бинарник PocketBase и Chromium в текущей среде недоступны; повторной проверки
этого обновления на настоящем PB/браузере здесь нет.
Эти проверки не являются подключением к VM или реальной КИС.
