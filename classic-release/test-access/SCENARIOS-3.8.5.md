# Обязательный демо-сценарий с несколькими получателями

Владелец уточнил приоритет 27.10.2026: хотя бы один демо-пользователь ОБЯЗАТЕЛЬНО
должен видеть несколько получателей. Предыдущий подбор трёх покупателей по
истории не гарантировал нескольких точек у одного покупателя и блокировал
создание аккаунтов поиском непустых историй. Этот подход заменён для пакета 3.8.5.

| Вход без пароля | Реальная область КИС |
| --- | --- |
| demo.test.point.v385@example.test | Одна точка покупателя A |
| demo.test.buyer.v385@example.test | Все активные точки покупателя B; минимум **две разные** обязательно проверены |
| demo.test.multi.v385@example.test | Покупатели C и B, все активные получатели обоих |

На второй кнопке написано «Несколько получателей (от 2)» и перечислены реальные
коды/названия двух проверенных точек. Стартует вторая проверенная точка B.
Это не несколько пользователей с одинаковым единственным получателем.

Подбор использует активные карточки покупателей, их список получателей и
активные карточки точек с совпадающим payer_id. Выбираются три покупателя,
один обязательно с двумя различными активными получателями. Текущие демо-
покупатели и известные производители исключаются. Если нужных карточек нет,
нет подстановки производителей/фиктивных точек. Фиктивны только email аккаунтов.

История и прайс НЕ являются условием создания этих входов. После установки
проверяются passwordless логины, точные области, одна точка первого аккаунта,
минимум две точки второго через `/service/clients`, оба покупателя третьего и
403 на чужого покупателя. До успешной проверки двух точек `READY` не выводится.
Строка `MULTI_RECIPIENT_DEMO_READY` содержит email и фактическое число получателей.
Затем история обеих проверенных точек читается через gateway и выводится отдельно:
`DEMO_HISTORY` (включая честный ноль), `DEMO_ORDER_LINES` или `DEMO_HISTORY_WARNING`.
Никаких заказов/историй/цен не создаётся, ошибки не подменяются.

Namespace v385 создаёт новые users/rights. Существующие пользователи, пароли,
права и менеджер не перезаписываются. Тестовая конфигурация содержит выборку;
повтор проверяет те же карточки и не меняет покупателей автоматически.
Выбор перед установкой сохраняется приватно на VM для продолжения после сбоя.
Общие preflight/backup/file rollback и запрет KIS POST сохранены. После неуспеха
проверки восстанавливаются предыдущие файлы, текущая бизнес-БД не откатывается.

Поставляется в общем `Karavay-Orders-3.8.5.ps1`: сначала интерфейс истории/
повтора, затем эти демо. Предыдущий отдельный v384-сканер историй не нужен.
Настоящая VM/выбранные названия и количество ещё требуют результата запуска;
локальные HTTP/SQLite/JS-ORM-фикстуры не являются ответами КИС.
