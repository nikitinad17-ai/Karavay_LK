# Тестовый кабинет 3.8.1

Актуальное уточнение владельца от 2026-10-16: подключена **тестовая КИС**.
Тестовый вход находится на обычном стартовом экране кабинета на VM.
Отдельный локальный HTML больше не требуется.

| Кнопка | Вымышленный email | Область КИС |
| --- | --- | --- |
| Один получатель (тест) | demo.test.point@example.test | Покупатель 2, получатель 2 |
| Все получатели Каравая (тест) | demo.test.buyer@example.test | Покупатель 2, все активные получатели |
| Два покупателя (тест) | demo.test.multi@example.test | Покупатели 2 и 3, все их активные получатели |

Названия и коды организаций/получателя установщик читает из API КИС с VM.
Предыдущее чтение владельцем: 2 — `ОАО"Каравай"`, код `0006`;
3 — `АО "ПАЛЯНИЦА"`, код `0007`. Получатель 2 — `ОАО"Каравай"`, код `006000`.
Все остальные активные получатели загружаются штатным `/service/clients`, а не
фиксируются по примерам 234243/384786/385317. Email покупателя не меняется.

## Однократная установка

Собрать исходный клиент и пакет:

```bash
npx vite build --config vite.classic.config.ts
node scripts/build-classic.mjs
python3 classic-release/test-access/build-package.py /path/to/output
```

Windows PowerShell после сохранения `Karavay-Test-3.8.1.ps1` в Downloads:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Test-3.8.1.ps1"
```

SSH/sudo может запросить пароль самой VM при обновлении. Пароль администратора
PocketBase и пароли тестовых пользователей не запрашиваются.
Установщик сверяет исходные файлы/схему, читает КИС, сохраняет резервную копию,
добавляет три аккаунта с правами одной транзакционной миграцией и проверяет три
входа/контекста и чтение получателей. Пароли аккаунтов случайные, хранятся только
в виде хеша PB и в браузер не передаются. Неподходящие/отключённые существующие
записи автоматически не переписываются и не включаются.

При наличии `users.manager_owner` и единственного активного пользователя
`Менеджер Каравай` он назначается владельцем тестовых пользователей по ID.
Email менеджера не вводится и не угадывается. Менеджеры, их назначения и `/manager/`
не меняются. Если такого менеджера нет, owner не назначается; установщик выводит
это явно. Это не мешает проверке клиентского кабинета.

Открыть `http://192.168.25.98:8090/`, выбрать кнопку. Оформление использует прежние
каталог, корзину, проверку, идемпотентную отправку и историю через `/service/*`.
Заказы отправляются в API тестовой КИС. Локальной подстановки товаров/заказов нет.
F5 и закрытие браузера сохраняют тестовый вход; «Выйти» удаляет сохранённый токен.
Неопределённая отправка сохраняется между открытиями браузера и не отправляется
повторно автоматически. Обычный вход по паролю остаётся доступен отдельно.

## Границы проверки

В изолированном PB 0.40.3 + Chromium проверяется весь сценарий, включая единственный
POST, повторное чтение созданного заказа, историю, состав, F5, перезапуск браузера,
три области прав, logout, мобильный вход, запрет чужих ID и отключения активности.
КИС в этих автоматических проверках — фикстура. Это не подтверждение записи в VM.
Установка на VM сама заказов не создаёт. Из облачной среды внутренняя VM недоступна.
Ранее реальный POST КИС отвечал `Не задан aId_Clt` при опубликованном формате
`Id_clt/DateOrd/Product`; серверная ошибка не маскируется успехом и не вызывает
попыток с выдуманными полями. Реальная приёмка — отправка в кабинете и появление
того же заказа в истории КИС после установки.

Тестовые маршруты включены только при `pb_data/karavay-test-access.json` с
`enabled: true, environment: "test-kis"`. Без этого файла возвращают 404.
В каждом входе проверяются пользователь, роль, точное множество прав и mapping.
Отключение `active` пользователя/прав/покупателя блокирует быстрый вход.
Для отключения уже выданных сессий отключить тестовых пользователей в PB.
Конфиг содержит только ID и подписи, не пароли/токены. Он не публикуется.

При ошибке установки возвращаются файлы приложения; текущие бизнес-данные и
журнал принятых заказов не откатываются. Резервная копия `/opt/.karavay-test-before-*`.
Подробный протокол: [VERIFICATION.md](VERIFICATION.md).
