# Тестовые пользователи с покупателями КИС — 19.10.2026

Владелец уточнил: payer 2 «Каравай» и payer 3 «Паляница» являются
производителями. Их выбор как покупателей был ошибкой. Создание заказа и
разбор ошибки Oracle поставлены на паузу; этот пакет не отправляет заказы.

## Три новых сценария

| Email | Доступ |
| --- | --- |
| `demo.test.point.v383@example.test` | Один покупатель, один проверенный получатель |
| `demo.test.buyer.v383@example.test` | Первый покупатель, все его активные получатели; проверены минимум две точки с каталогом |
| `demo.test.multi.v383@example.test` | Два разных покупателя, все их активные получатели |

Фактические организации выбираются на VM из текущего `/payers`, с проверкой
активной карточки, `/payers/{id}/clients`, принадлежности активных получателей
по `/clients/{id}` и доступного каталога с ценами на завтра (Москва).
Null минимум означает целые лотки, поэтому каталог с неизвестной укладкой
не считается пригодным. Нулевой минимум допускает штуки.

Исключены ID 2/3 и названия «Каравай»/«Паляница», а также ранее отклонённые
НЕВА/ПРОМТЕХСБЫТ (ID 299271/300182 и варианты названий). Никаких придуманных
названий/ID покупателей и получателей. В доступном API нет отдельного признака
производителя/покупателя; неизвестная бизнес-классификация не выдумывается,
префиксы кодов не интерпретируются. Выбранные названия, ID и получатели явно
печатаются перед установкой и в описаниях кнопок; фактический список известен
только после запуска с доступом к КИС. Новые другие исключения можно добавить
по подтверждению владельца, не выдавая название за универсальный классификатор.

История может быть пустой: подбор не вызывает `/orders` и не зависит от
создания заказа. Данные истории не подменяются. Наличие заказов этими сценариями
не обещается. Нужны два покупателя и минимум две пригодные точки у первого;
если они не найдены, подбор останавливается до изменения приложения/пользователей.

## Установка

Скачать `Karavay-Real-Buyers-20261019.ps1` в Downloads и выполнить:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Real-Buyers-20261019.ps1"
```

Нужен только обычный вход SSH/sudo на VM. Пароли PB/тестовых пользователей
не запрашиваются и не сохраняются. Одноразовый неизвестный пароль нового
аккаунта генерируется внутри PB; вход через существующий `/service/test-access`.

Пакет изменяет только helper тестового входа, конфигурацию выбранных трёх
сценариев и добавляет их миграцию. HTML клиента, остальные gateway hooks,
менеджер, старые учётные записи/права/пароли остаются прежними. Старые демо
записи не удаляются, но их кнопки заменяются; существующий клиент на обновлении
страницы сверяет тестовую сессию с новым списком и очищает старый вход.
Новые аккаунты используют отдельный namespace v383. Общие покупатели остаются
реальными записями КИС, в PB добавляются только проверенные связи.

Повтор проверяет те же организации и получателей; автоматическая смена выбора
при их отключении запрещена. Изменённые отдельно права/учётные записи не
перезаписываются. До остановки PB проверяются версия/схема/хэши относящихся к
задаче файлов и отсутствие посторонних ожидающих миграций. Есть резервная копия;
при сбое возвращаются файлы/конфигурация, бизнес-БД и журнал заказов не откатываются.
Новые записи после успешно применённой миграции могут сохраниться при откате
файлов; старые пользователи/права не меняются.

Проверка после установки: три входа без пароля, области покупателей/получателей,
каталог через публичный gateway и запрет чужой точки для первого пользователя.
Локальные проверки используют изолированную фикстуру КИС и не подтверждают
фактический подбор/установку на VM. Прямого доступа к внутренней VM из этой
среды нет.

## Выполненная локальная проверка

PASS: HTTP fixture для фактического urllib-reader; запрет 2/3 и названий
производителей, чужих/отключённых получателей, неизвестной укладки; два
покупателя/две точки, повтор без смены выбора, отсутствие запросов истории,
POST и пересылки PB-токена. Реальный отдельный PB 0.40.3 и Chromium: переход
381→383 без изменения старых записей, три входа, проверка областей, каталог,
сброс старой демо-сессии, F5/закрытие браузера, повтор, настоящий main/apply и
откат файлов. Полный заказ в браузере этой проверки использует только
изолированную КИС-фикстуру. TypeScript/34 теста/сборка PASS. PowerShell проверен
нативно с подменой SSH/SCP. Реальный подбор покупателей в КИС VM предстоит.
