# Совместимость с отдельно установленным оформлением

Первый общий установщик пароля остановился на клиентском preflight: показанный
оператором SHA-256 отсутствовал в `known_html`. Обе установки оставались
не выполнены (`manager_done=False`, `client_done=False`).

Сборка идентифицирована по оригинальным ранее выданным пакетам:

| Элемент | SHA-256 |
| --- | --- |
| HTML из `Karavay-Orders-3.8.5.ps1` | `82593d4b3ae76b058786cffadffdf0c5739e1ee0867908366492c82d1b409a6a` |
| CSS из `Karavay-Style-Bright-20261028.ps1` | `507a8943761dbc65be5bde244a6bb9bf5de04f782c335ec215706a35fbe846cd` |
| HTML после штатного `apply-style.py` | `4b29604a0200c5b1b4d4b629d3a06597470ad28f519f4d4a8d046483258e31fb` |

Хеши исходных HTML/CSS проверены по встроенным манифестам. Код `apply-style.py`
совпал с опубликованным исходником. Применение его `transform` воспроизвело
ровно хеш со скриншота VM; изменения JavaScript этим преобразованием не вносятся.

Этот конкретный хеш добавлен в список допустимых предшественников в
`scripts/build-classic.mjs` и пересобранном `classic-release/MANIFEST.json`.
Проверка неизвестных файлов остаётся обязательной. Обновлённый список используется
обычным клиентским пакетом и общим установщиком пароля.

Проверено обновление восстановленного HTML до клиента с минимумом пароля 6
через настоящий локальный HTTP и атомарную запись файла: preflight, установка,
резервная копия, контроль выдаваемого HTML и повторный запуск.
Успешную установку на VM по-прежнему подтверждает её финальный вывод.
