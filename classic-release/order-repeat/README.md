## Изменения

- «Статус КИС» убран из таблицы и карточки.
- Вся строка открывает заказ мышью или Enter/Space. Кнопка повтора справа не
  вызывает открытие карточки; в самой карточке есть такой же повтор.
- Повтор открывает выбор даты и группы продукции, читает состав и актуальный
  прайс через текущий `/service/*`. Совпадение по точному коду товара; ID новой
  позиции, цена, укладка и минимум берутся из нового прайса. Старые line IDs и
  цены не используются для POST. Дубли исторических строк суммируются по коду.
- Общее число штук сохраняется; новая укладка меняет представление лотки/штуки.
  Недопустимое количество полного лотка не округляется. Отсутствующие товары,
  неизвестная укладка, неоднозначные коды и отсутствие цены показаны списком.
  Частичный перенос требует отдельного нажатия. Изменившийся минимум остаётся
  виден в корзине и блокирует отправку до исправления количества.
- Замена непустой корзины требует подтверждения. Отмена, отказ прайса, поздний
  ответ после отмены или смена контекста не переносят старые данные. Viewer и
  незавершённая отправка блокируют повтор. Сам повтор не создаёт POST заказа.
- Сохранены шесть разделов, дизайн, обычный вход, тестовые сессии и ручной выбор
  покупателя. Устаревшая preferredDate старого helper больше не задаёт прошлую
  дату при тестовом входе: используется завтра по Москве.

## Один установщик

`Karavay-Orders-3.8.5.ps1` последовательно выполняет два независимых этапа:

1. Атомарная замена только HTML. Проверяются известный SHA, фактически отданный
   HTML, прежние IDs демо и hashes helper/config/миграций/менеджера. Нет restart,
   миграций, доступа к БД и запросов к КИС. Ошибка/Ctrl-C возвращает прежний HTML,
   не откатывая чужие изменения конфигурации или менеджера.
2. Создание трёх разных сценариев v385: одна точка A; все точки B с
   **обязательными минимум двумя разными активными получателями**; покупатели C+B.
   См. [SCENARIOS-3.8.5.md](../test-access/SCENARIOS-3.8.5.md). Названия двух точек
   написаны на второй кнопке. Создание НЕ ждёт истории или прайса: сначала
   passwordless входы и проверка >=2 точек через scoped gateway, потом отдельное
   чтение реальной истории. Ошибка/ноль истории не отменяют созданные сценарии.
   Профили/истории/цены не подменяются. Старые аккаунты и менеджер сохраняются.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Orders-3.8.5.ps1"
```

После этапа 1: `CLIENT_3_8_5_UPDATED` или `CLIENT_3_8_5_ALREADY_OK`.
После этапа 2: `MULTI_RECIPIENT_DEMO_READY` с count >=2 и `SCENARIOS_READY`.
Обновить Ctrl+F5. `-ClientOnly` выполняет только UI-этап; `-SearchMinutes 1..60`
задаёт бюджет подбора карточек (15 по умолчанию).
Старый отдельный файл v384 поверх 3.8.5 не запускать: его hash guard остановит
попытку установки. Текущий объединённый пакет содержит новый HTML и manifest.

Установка не отправляет заказы. Неисправность создания `aId_Clt` и доступность
цен КИС этим изменением не исправляются. Для переноса требуется актуальный прайс;
при его ошибке корзина сохраняется, показывается ошибка.

## Проверка

`npm run check`: TypeScript, 52 теста, сборка. Проверены клики по строке/клавиатура,
обе кнопки, актуальная дата/группа/цена, точное количество, недоступные товары,
изменение лотков, отказ прайса, подтверждение замены, отмена/поздний ответ, viewer,
pending request, foreign detail, прежние сценарии заказа и passwordless restore.
9 Python HTTP/filesystem tests: actual apply/repeat, no changes outside HTML,
read-only preflight, no migration execution, rollback/Ctrl-C, concurrent manager
change, unknown SHA/tampered package/symlink, ordinary login without demo metadata.
Новая сборка classic и inline CSP проверены. Сценарии демо проверены отдельно
actual main + HTTP/SQLite-фикстурами с пустыми историями: создание/повтор при
>=2 точках и обязательный отказ/откат при одной точке. Обе точки также проверены
реальными JS read handlers с ORM/transport-фикстурой.

Новый запуск на реальной VM/КИС не выполнен. Бинарник PocketBase/Chromium и
PowerShell в текущей среде недоступны: нет нового визуального браузерного прогона
или нативного запуска PS1. Fixture-результаты не являются доказательством КИС.
