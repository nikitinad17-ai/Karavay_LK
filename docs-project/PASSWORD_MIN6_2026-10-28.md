# Пароль от 6 символов — 28.10.2026

По запросу владельца временно установлен минимум **6 символов** вместо 12.
Более длинные пароли по-прежнему разрешены; существующие пароли не меняются.

В менеджерском пакете обновлены форма создания пользователя, форма смены
временного пароля и общий серверный обработчик `/service/account/change-password`,
который используется обоими кабинетами. Максимум обработчика остаётся 128;
проверка текущего пароля, запрет совпадения старого/нового и обновление токена сохранены.

Добавлена миграция `1793235600_users_password_min6.js`: меняет только минимум
поля `users.password` в PocketBase. Хеши паролей, пользователи, роли и права
не перезаписываются. Это также разрешает шестизначный новый пароль при нативном
сбросе через письмо. Установщик проверяет применение минимума 6.

В клиентской ветке отдельно обновлена форма Classic. Для полного изменения
нужно установить оба обновления: менеджерский пакет с серверной миграцией и
пересобранный клиентский HTML. Изменение одного HTML не снимает серверный минимум.
Клиентский пакет `Karavay-Orders-3.8.5.ps1` следует запускать с `-ClientOnly`,
если требуется только обновить клиент и сохранить текущие демо.

Проверки добавлены для создания пользователя с 6 символами, отклонения 5,
смены клиентского и менеджерского пароля, сброса через письмо и сохранности
существующих хешей при миграции. Дополнительный Chromium-сценарий проверяет
обе реальные формы и повторный вход с шестизначным паролем:

```bash
MANAGER_CHROME=/path/to/chrome-headless-shell CLIENT_HTML=/path/to/client.html PB_BINARY=/path/to/pocketbase python3 manager-live/tests/integration.py
```

Фактически прошли 98 HTTP-проверок PocketBase 0.40.3 и Chromium-сценарий
для обеих форм: 5 символов отклоняются, 6 сохраняются, повторный вход успешен.
Существующие хеши паролей и ключи токенов сохранены при миграции с минимума 12.
Также прошли 52 теста клиента, 22 общих теста менеджерской ветки, 16 проверок
сессии, 9 установщика и 14 сценариев PowerShell 7/Linux.
Корневой старый E2E-набор по-прежнему останавливается на демо-кнопке React 3.5;
он не проверяет эти формы.

Обновление исходников само по себе не меняет VM. Файловый откат менеджера
не возвращает предыдущий минимум в БД; при возврате политики его нужно изменить
явно, вместе с формами и серверными проверками. Существующие пароли сохраняются.
