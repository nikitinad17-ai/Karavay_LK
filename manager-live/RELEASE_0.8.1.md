# КАРАВАЙ — менеджер 0.8.1: тестовый вход на странице

17 октября 2026. Основа — 0.8.0 / исправление установщика r1,
21ac60eddbf2c31d44f5df73cebabe1b98bc922b.

На обычной странице `/manager/` добавлена кнопка «Тестовый вход менеджера».
На тестовой VM оператор включает её для существующего «Менеджер Каравай».
Кнопка входит одним нажатием с пустыми полями email/пароля; отдельный личный HTML
для этого больше не нужен. Обычная форма и ранее выданные личные входы сохранены.

## Поведение

- Режим выключен по умолчанию. Локальный Enable-Test-Login.py сверяет установленный
  пакет и существующего активного менеджера/роль, затем записывает один конфиг
  manager-test-login.json в pb_data (0600), вне публичных файлов.
- Включённый режим разрешает посетителям тестовой страницы войти этим менеджером.
  POST принимает только пустой JSON с Origin, совпадающим с настроенным сервером.
  Выбрать другой ID, роль или email из запроса нельзя.
- Паролей и готовых токенов в распространяемых файлах нет. Токен выдаётся сервером
  после нажатия, действует 8 часов, не обновляется через auth-refresh. Страница
  хранит его в sessionStorage; F5 проверяет manager/state, выход очищает сессию.
- Отключённый аккаунт/роль, обязательная смена пароля или повреждённый конфиг
  блокируют тестовый вход. Бизнес-маршруты продолжают проверять текущие права.
- `Enable-Test-Login.py --disable` убирает кнопку и запрещает выдачу новых токенов.
  Уже выданный токен действует до истечения 8 часов либо обычного отзыва доступа.
- Скрипт не создаёт пользователей, не изменяет пароли или назначения. Замеченное
  на скриншоте несоответствие quick_point/«Все получатели A060» не исправляется
  автоматически. Повторная настройка трёх демо в рекомендованном запуске не идёт.

## Установка

Сохранить Karavay-Manager-0.8.1-Complete-20261017.ps1 в Downloads:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Manager-0.8.1-Complete-20261017.ps1" -TestLoginOnly
```

Один пакет: проверка совместимости, backup, обновление менеджера, включение кнопки.
Нужны обычные SSH/sudo данные VM; админка PocketBase для этого шага не спрашивается.
После MANAGER_TEST_LOGIN_READY открывается http://192.168.25.98:8090/manager/ .
При старом кэше обновить Ctrl+F5. Дизайн 0.8, клиентский HTML и gateway сохраняются.
Скрипт установки принимает точные контрольные суммы уже опубликованного 0.8.0.
Сверен текущий клиентский источник 3.8.2 (195f5f801c152a1f6fa544cd6a9f2ed1541ffd79):
его gateway_preserved и orders-handler совпадают с допустимыми hashes менеджера.
Остальные клиентские hooks и index.html учитываются как защищённые файлы и
не входят в заменяемый пакет менеджера.

`-PreflightOnly -TestLoginOnly` проверяет совместимость без установки/включения.
Старый режим полной настройки демо остаётся отдельным запуском без TestLoginOnly;
его текущие данные должны сначала пройти сверку с КИС.

## Проверка

Проверено на отдельном PB 0.40.3 с фикстурой КИС, не на VM пользователя:

- Кнопка с пустыми email/паролем в Chromium, реальный токен, F5 без повторной
  выдачи токена/refresh, выход и повторное нажатие, мобильная страница без overflow.
- Режим по умолчанию выключен; чужой/отсутствующий/null Origin, переданный ID,
  query, повреждённый конфиг, другой тип пользователя, неактивный менеджер/роль и
  обязательная смена пароля не дают тестовый вход. Выключение режима проверено.
- Снимки users/rights/payers/clients до/после включения и входа совпадают;
  прежний пароль менеджера работает. Конфиг 0600, GET не возвращает токен/email.
- 70 прежних HTTP-проверок, 18 проверок двухэтапного UI, клиентский вход/изоляция,
  16 проверок сессии, 8 проверок установщика с rollback прошли.
- 17 сценариев настоящего PowerShell 7.4.6/Linux (Legacy native argv): новый
  TestLoginOnly вызывает install + enable без Configure-Workspace/скачивания
  личных файлов, открывает URL; preflight ничего не включает. SSH/SCP — фикстуры.
- npm run check: TypeScript, 22 теста и production build прошли.

Из этой среды установка 0.8.1 на VM и Windows PowerShell 5.1 не выполнялись.
Старый React E2E-набор клиента не изменён; его известные сбои описаны в 0.8.0.
