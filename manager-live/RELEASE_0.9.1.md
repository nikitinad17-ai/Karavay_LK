# Менеджер 0.9.1 — список и форма по двум скриншотам

Дата: 28.10.2026. База: `71bb720` / менеджер 0.9.0.

Основной экран — «Пользователи»: синяя боковая панель с одним разделом,
фильтр ролей, таблица и жёлтая кнопка «Создать пользователя». Колонки:
логин, email, роль, подтверждён, покупатели, получатели, действия.
Роли подписаны «Получатель (Client)» и «Покупатель (Payer)».
У получателя назначения показаны в колонке получателей, у покупателя — покупателей.

Окно «Новый пользователь» содержит четыре поля, расположенные как на втором
скриншоте: логин, email, роль, пароль. После «Создать» запись сохраняется,
окно закрывается. Дополнительный мастер назначения автоматически не открывается.
Имя нового пользователя заполняется логином; имена существующих пользователей
сохраняются. Администратор и менеджер недоступны для создания из кабинета менеджера,
как в списке на образце. Прежнее ограничение пароля 12 символов сохранено.

В таблице остаются «Инфо», «Изменить», «Удалить». Назначения доступны внутри
«Изменить» под раскрывающимся пунктом «Покупатели и получатели». Существующие
настройки активности и сброс пароля сохранены там же. Удаление требует подтверждения,
проверяет принадлежность пользователя области менеджера и удаляет его права
в той же транзакции. Чужого пользователя, менеджера или администратора удалить нельзя.

## Существующие демо

Демо остаются строками в общей таблице. Для доступных тестовых аккаунтов сохранена
кнопка «Войти». Поддержаны как входы менеджера 0.9.0, так и существующий клиентский
`/service/test-access`. При открытии тестового клиента используется его текущая
авторизация; новая вкладка не заменяет сессию менеджера.

**Обычный запуск установщика 0.9.1 не создаёт, не удаляет и не перенастраивает демо.**
Он обновляет менеджер и сохраняет кнопку тестового входа менеджера. Старый явный
`-ResumeSetup` оставлен для отдельно запрошенной настройки набора 0.9.0.
Новые карточки, обзор и отдельные экраны покупателей/получателей из основного
интерфейса убраны. Клиентский кабинет и его функции заказов не заменяются.

## Данные и доступ

Для сохранения выбранного Client/Payer до назначения точек добавляется одно
необязательное скрытое поле `users.account_type`. Существующие записи не
переклассифицируются и не перезаписываются; если поле пустое, подпись берётся
из имеющихся прав. Технические роли `owner/manager/viewer` и клиентский контракт
авторизации сохранены. Режим «Только просмотр» существующих записей не повышается.
Это поле не выдаёт доступ: его по-прежнему определяют реальные активные `rights`.
Для Client разрешаются конкретные получатели, для Payer — общее право выбранного
покупателя. Новый аккаунт без назначений остаётся без бизнес-доступа.

Добавление поля не сбрасывает хеши паролей/ключи токенов. Нативные пользовательские
запросы не могут менять управляемый тип аккаунта. Установщик проверяет конфликт
поля, создаёт резервную копию и сохраняет прежние client/gateway файлы.
Отдельная версия обработчика заказов не является причиной отката клиентского
выпуска: этот файл не заменяется и его текущий хеш проверяется до/после установки.

## Установка

Скачать `Karavay-Manager-0.9.1-Users-20261028.ps1` в «Загрузки». В Windows PowerShell:

```powershell
cd ([environment]::getfolderpath('userprofile') + '\downloads')
powershell -noprofile -executionpolicy bypass -file .\karavay-manager-0.9.1-users-20261028.ps1
```

Успех: `MANAGER_RELEASE_INSTALLED: 0.9.1`, затем `TEST LOGIN READY`.
Открыть `/manager/`, обновить Ctrl+F5. Нужен обычный SSH/sudo, пароль админки PB
не требуется. `-PreflightOnly` не меняет службу/данные. Установка на внутреннюю VM
из среды разработки не выполняется; её фактический результат подтверждает оператор.

Проверки выполняются на отдельном PB 0.40.3, с фикстурой КИС и Chromium.
Окончательные результаты и команды — в README.
