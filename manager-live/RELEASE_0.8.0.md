# КАРАВАЙ — разбор проблем и выпуск менеджера 0.8.0

Дата анализа: 16 октября 2026, Europe/Moscow. Основа: опубликованный менеджер
`7dd630e4d891be71ddd7e7b19a553cd5f67258bf`. Изменяется кабинет менеджера и его
установка. Основной клиент 3.8.0 и его обработчики заказов не переписываются.

## Исправление установщика r1 — 17 октября 2026

Скриншот `1(8).PNG` подтверждает на VM preflight, backup
`/opt/.karavay-manager-before-20261017-062456` и `MANAGER_RELEASE_INSTALLED: 0.8.0`.
Затем Configure-Workspace.py остановился на проверке ID до ввода учётных данных PB.
Создание личного входа и демо этим запуском не подтверждено.

Причина воспроизведена на исходном распространяемом PS1: в `--run-id` передавалось
имя папки с `0.8.0`, а сервер допускает только буквы, цифры, `_` и `-`. Проверка
сервером корректна; исправлен вызывающий PowerShell. Уникальный run_id теперь
создаётся отдельно от имени папки и проверяется до первой команды VM.

Получение результата также исправлено: сначала один JSON-отчёт и сверка run_id,
версии и статуса; затем по одному файлу на scp. Ранний отказ больше не вызывает
попытки скачать несуществующие личные HTML; старый отчёт не открывает старый вход.
Код 2 с действительным частичным отчётом сохраняет доступ к готовому менеджеру.

`Karavay-Manager-0.8.0-Complete-20261017-r1.ps1 -ResumeSetup` продолжает только
настройку уже установленного 0.8.0. В этом режиме install.py/sudo не вызываются,
сервис не перезапускается. Интерфейс и серверные бизнес-файлы 0.8.0 не изменены.
Обычный полный запуск и `-PreflightOnly` сохранены.

Проверка r1: 14 сценариев; настоящий PowerShell 7.4.6 на Linux с Legacy-передачей аргументов
нативным процессам и пробелами в USERPROFILE; SSH/SCP и результаты VM — изолированные
фикстуры, реальная VM не вызывается. Проверяются полный/продолжающий запуск,
preflight, частичный/ранний отказ, устаревший/неверный отчёт, ошибки SSH/копирования,
исключение личных файлов из ZIP и фактический старый PS1 с дефектом.
Повторно прошли npm run check и workspace.py на отдельном PB 0.40.3 с Chromium:
входы, три демо и изоляция, отсутствие дублей, личный file:// вход, F5/logout,
«Добавить» и двухэтапное создание. Windows PowerShell 5.1 и r1 на VM ещё не запускались.

## Сценарии новой версии

- Обзор использует реальные счётчики назначенных покупателей, пользователей и
  ожидающих назначения; демонстрационные записи в рабочий ответ не подмешиваются.
- Покупатели: полный справочник КИС, поиск и фильтры «Мои» / «Доступные»;
  «Добавить» в строке; после добавления — «Открыть», «Создать пользователя»,
  разрешённое изменение контактов. Получатели других покупателей массово не читаются.
- Создание из строки покупателя/получателя: первая форма содержит только данные
  учётной записи. Пользователь сохраняется без бизнес-прав. Во втором отдельном
  окне нужный покупатель/получатель предварительно выбран; права записываются
  только кнопкой сохранения. Закрытие оставляет «Ожидает назначения».
- Пользователи: отдельные колонки, роль, статус, подтверждение email по фактическому
  verified, покупатели/получатели, информация, изменение, назначения, отключение,
  сброс пароля. Снятие всех назначений и отмена правок сохраняют подтверждение.
- Получатели: список из КИС с кодом/адресом и переходом к созданию пользователя.
- Демо: отдельный раздел показывает реально существующие аккаунты менеджера.
  Пустой список прямо сообщает об отсутствии настройки.
- Обычный email/пароль, «Запомнить меня», refresh, logout и несколько вкладок
  сохранены. Неизвестная/неактивная роль и чужая область блокируются сервером.

## Вход и установка

Полный PS1 содержит проверенный пакет внутри себя: выбирает обычный Downloads,
проверяет checksum, передаёт файлы, устанавливает с резервной копией, затем
настраивает вход и демо в том же интерактивном SSH-сеансе. Пароль админки PB вводится
один раз в терминале. Пароль SSH и пароль менеджера автоматически не меняются.

Если SSH не принимает существующую учётную запись, `Install-On-VM.py` позволяет
выполнить тот же закреплённый выпуск из консоли VM. Это отдельный путь доставки,
а не изменение настроек SSH. Администратор может получить read-only отчёт через
`Check-Manager.py`: он не выбирает password/tokenKey и не читает приватные планы.

Настройка создаёт вне pb_public:

- `Karavay-Manager-Access.html` — личный доступ существующего менеджера на 8 часов.
  Используется стандартная PB impersonation, выданная superuser; в файл попадает
  только ограниченный user-token. Он не обновляется через auth-refresh; каждый
  вход/F5 проверяется через manager/state. После logout F5 не входит автоматически.
- `Karavay-Test-Login.html` — существующая приватная клиентская копия с тремя
  кнопками сценариев. Обычный клиент и его сохранённые бизнес-проверки не заменены.
- `Karavay-Manager-Setup-Report.json` — результат конкретного запуска без токенов
  и паролей. Только совпавший run_id позволяет открыть скачанный личный вход.

Все приватные файлы имеют mode 0600. В release ZIP/PS1, GitHub, Drive или Library
они не включаются. Новая миграция схемы не добавлялась; остаётся прежняя добавочная
миграция manager_owner для обновления со старой версии.

## Фактическая проверка

- 70 HTTP-проверок менеджера на отдельном PB 0.40.3 и локальной заглушке КИС:
  изоляция, роли/active, черновики, назначения, контакты, сброс/смена пароля,
  запрет native-записи. 18 проверок двухэтапного интерфейса через реальный HTTP.
- 16 проверок сессии и загрузки названий: сохранение, F5, повторный вход, logout,
  другая вкладка, временный сбой, поздние ответы после выхода/обновления.
- Отдельная интеграция workspace.py на настоящем PB: обычный вход, сохранение
  прежнего пароля, проверка менеджера, три закреплённых сценария, их login/изоляция,
  повтор без дублей, отказ чужим правам и отключённому аккаунту, приватные файлы/CSP.
- Chromium с реальным локальным PB: обычный/ошибочный пароль и неверная роль,
  «Добавить» покупателя, создание из его строки, два отдельных окна, мобильное меню,
  вход из file://, F5, logout и повторный личный вход. Без исходящих заказов.
- Восемь проверок установщика: read-only preflight, допустимые hashes gateway,
  неизвестные файлы, чужие миграции, запрет произвольного root, полный цикл записи
  в изолированный root с backup и восстановление после частичной записи.
- npm run check: TypeScript, 22 теста и production build проходят.
- Сборщик распаковывает собственный результат, сверяет ZIP и каждый checksum;
  разрешает только явный перечень исходников и не включает pb_data/личные файлы.

На рабочую VM этот выпуск из среды разработки не установлен. Установку 0.8.0
подтвердил скриншот пользователя 17 октября; настройка входа/демо остановилась.
Windows PowerShell 5.1 не запускался; проверка PS1 в PowerShell 7 описана выше.
В старом React E2E-наборе клиента остаются ранее выявленные 6 сбоев локаторов/
ожидания заголовка (1 passed, 1 skipped); эти src/tests не менялись и не загружают
manager-live. Новые сценарии менеджера проверены отдельным настоящим браузером.
