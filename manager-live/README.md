# КАРАВАЙ: менеджер 0.5 + клиент 3.7.3 — автоматические справочники

База выпуска: установленный менеджер 0.4 и клиент 3.7.2 Matrix от 14.10.2026.
Код main React 3.5 не является клиентским интерфейсом этого пакета.

## Поведение

- «Добавить покупателя» автоматически читает GET /api/v1/payers через PocketBase.
  Поиск по коду, названию или адресу, без ручного ввода ID. Все ранее подключённые
  ID/коды исключены: существующие чужие записи нельзя захватить.
- Список подключения доступен только активному менеджеру с активной role relation.
  Возвращаются только ID, код, название, адрес; финансовые поля КИС не выдаются.
- Сохранение повторно читает КИС и берёт код/название по выбранному ID; подмена
  имени браузером не используется. Проверяется действующий получатель КИС,
  затем покупатель и собственное право all сохраняются атомарно.
- В форме пользователя получатели автоматически загружаются при выборе покупателя.
  Показаны загрузка, число вариантов и ошибка; устаревшие ответы отбрасываются.
  Для отдельного доступа пользователь выбирает конкретного получателя.
- Пользователи/пароли/роли/rights хранятся в PocketBase; в КИС новые карточки не
  создаются. Из КИС загружаются бизнес-справочники, а не учётные записи пользователей.
- Клиент 3.7.3 автоматически читает свой /service/context и /service/clients после
  входа и F5. При возвращении на вкладку после 30 секунд перечитывает доступы.
  Полный справочник КИС клиенту не выдаётся. Параметры DateOrd и Group 3.7.2 сохранены.
- При назначении конкретного получателя сохраняется legacy client relation для
  совместимости с уникальным индексом rights; массового копирования получателей нет.
- Первый вход с временным паролем пока выполняется через /manager/ для его смены,
  затем пользователь входит в /. Смена пароля вращает токен и требует нового входа.
- Заказы: сохраняется режим чтения. POST/PUT заказов не добавлены этой версией.
- Убрана вводящая в заблуждение кнопка «Подключить» получателя; список нужен для
  просмотра, назначение выполняется в форме пользователя. Исправлен pattern логина.

## Контракт

GET /service/manager/buyers — кандидаты КИС, ещё не зарегистрированные в PB.
GET /service/manager/state — назначенные менеджеру покупатели/пользователи/права.
GET /service/manager/clients?payer=<PB ID> — получатели КИС в области менеджера.
POST /service/manager/action — создание/редактирование пользователей и покупателей,
назначение прав, отключение пользователя, сброс пароля; attach_client оставлен
для совместимости API, но убран из интерфейса.
POST /service/account/change-password — {oldPassword,password}.

Ограничения: /payers должен вернуть полный массив до 10000 элементов и 2 MiB.
Пагинация upstream не подтверждена. Никакого молчаливого обрезания выдачи нет.
Наблюдавшийся формат КИС .14 нормализуется только в числовых токенах вне строк;
остальной некорректный JSON отклоняется. state=1 как активность получателя требует
подтверждения КИС. Почтовая доставка требует настроенного SMTP.

## Проверки

47 HTTP-проверок на изолированном PocketBase 0.40.3; 12 DOM-проверок менеджера и
вход/автозагрузка/изоляция клиентского кабинета через jsdom с реальными локальными
HTTP-запросами. Проверяются чужие данные, owner/viewer denial менеджерского списка,
уникальность подключения, создание пользователя/прав, смена/сброс пароля.
КИС заменена локальной заглушкой, реальная VM этими тестами не вызывается.
`npm run check`: typecheck, 22 теста React и сборка проходят.
Визуальный браузерный прогон и реальная установка нового пакета не выполнены.

## Установка на VM

Скачать ZIP, scp на VM, извлечь и запустить scripts/install.py --install под sudo.
Без --install выполняется только preflight. Требуются PB 0.40.3, исходная схема,
известные hashes менеджера 0.4/0.5 и установленный клиент 3.7.2/3.7.3.
Gateway каталога должен совпадать с 3.7.2 Matrix; context/clients/orders сохраняются.
Новые миграции не запускаются. При установке сервис кратко останавливается,
создаётся root-only backup pb_data и заменяемых файлов, выполняются health/401/HTML
проверки. При отказе возвращаются прежние файлы и запускается служба; DB snapshot
остаётся резервной копией, автоматического отката живой базы нет.

Ветка: feature/manager-cabinet-v0.3, main не изменяется.
