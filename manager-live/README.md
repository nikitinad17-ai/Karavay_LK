# КАРАВАЙ — кабинет менеджера 0.8.0

Менеджер покупателей, получателей и пользователей. Основа дизайна — сохранённый
прототип manager-demo 0.3; данные и авторизация — текущий PocketBase/КИС.
Заказы в кабинет менеджера не добавляются. Клиентский HTML 3.8.0 сохраняется.

[Разбор проблем, изменения и проверка выпуска](RELEASE_0.8.0.md).

## Основные действия

1. В «Покупатели» найти компанию КИС и нажать **Добавить** в её строке. Для уже
   назначенной компании доступны открытие, создание пользователя и разрешённое
   изменение контактов. Email организации показывается/сохраняется только реальный.
2. Создать пользователя обычной кнопкой либо из строки покупателя/получателя.
   В первом окне только имя, email, технический логин, роль и временный пароль.
3. После реального сохранения открывается другое окно назначений. Выбрать одного
   или нескольких покупателей, всех получателей или конкретные точки и сохранить.
   Закрытие окна оставляет пользователя без бизнес-доступа со статусом ожидания.
4. Пользователи: поиск/роль, информация, изменение, назначения, включение/отключение,
   сброс пароля. Доставка email должна отдельно подтверждаться настройкой SMTP.
5. Обзор и раздел «Демо-пользователи» показывают фактические данные текущего менеджера.

«Запомнить меня» хранит только PB-токен, пароль не сохраняется. Обычный refresh,
logout и выход в других вкладках сохранены. Вход — по email пользователя manager;
учётная запись админки PB используется только при настройке в терминале.

## Полная установка из Windows

Сохранить `Karavay-Manager-0.8.0-Complete-20261017-r1.ps1` в обычный Downloads:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Manager-0.8.0-Complete-20261017-r1.ps1"
```

Это один файл с пакетом внутри. Сначала проверка совместимости и backup, затем
обновление менеджера и настройка личного входа/трёх демо. При запросе вводятся
существующий пароль SSH/sudo и один раз учётные данные админки PB — в терминале.
Их смена для установки не требуется. PB кратко перезапускается.

Личные HTML скачиваются в `Downloads\Karavay-Manager-0.8.0-<время>\Private`:
`Karavay-Manager-Access.html` открывается автоматически после подтверждения текущего
run_id; `Karavay-Test-Login.html` содержит три кнопки тестовых сценариев клиента.
Личный вход менеджера действует 8 часов, проверяет действующие роль/права и не
меняет пароль. Личные файлы с доступом не входят в распространяемый пакет.

Ожидаемые результаты:

```text
MANAGER_RELEASE_INSTALLED: 0.8.0
MANAGER_ACCESS_READY: ...
MANAGER_WORKSPACE_READY: 0.8.0
DEMO_USERS_READY: 3 ...
```

Частичный результат прямо обозначается: готовый менеджер не означает готовые демо.
Неизвестные файлы и чужие неприменённые миграции останавливают установку до записи.
Поддерживается сохранённый orders-handler клиента 3.8.0; защищённые клиентские файлы
проверяются до/после. Существующие учётные записи и пароли не переустанавливаются.

Для read-only проверки полного PS1 добавить `-PreflightOnly`.
Если уже получено `MANAGER_RELEASE_INSTALLED: 0.8.0`, а настройка остановилась
на `Некорректный ID запуска`, повторная установка не нужна:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Manager-0.8.0-Complete-20261017-r1.ps1" -ResumeSetup
```

Этот режим только передаёт проверенный пакет и запускает настройку под обычным
оператором. Он не вызывает install.py/sudo и не останавливает PocketBase.
Перед настройкой проверяется уже установленный менеджер 0.8.0; существующий
приватный план демо переиспользуется. ID запуска — отдельный GUID без точек.
Сначала скачивается и проверяется отчёт этого запуска, затем каждый личный файл
отдельно. Если настройка остановилась до отчёта, личные HTML не скачиваются.

Для загрузчика из GitHub: `scripts/Download-Karavay-Manager.ps1 -SourceRevision
<полный SHA> -Install -ConfigureWorkspace`. Для повторной настройки без установки:
тот же загрузчик с `-ConfigureWorkspace` и без `-Install`.

## Если SSH не принимает пароль

Не перезапускать ту же передачу вслепую. Войти в обычную консоль VM как
lindevadmin и использовать `scripts/Install-On-VM.py --revision <полный SHA>
--apply --configure`. Скрипт скачивает и сверяет один закреплённый выпуск без SSH,
запускает тот же установщик и настройку. Сам файл берётся из того же Git-коммита.
Если консоль открыта под root, сначала выполнить `sudo -iu lindevadmin`, затем
запустить полную команду. Так и установочный пакет, и личные файлы останутся в
доступном оператору home. Полный bootstrap под root останавливается до изменений.

Диагностика на VM: `python3 scripts/Check-Manager.py`. Это только чтение статусов,
файлов, настроек manager и количества демо; пароли/токены не выбираются.

## Демо и совместимость

Целевой существующий менеджер — **Менеджер Каравай**. При неоднозначном имени
можно указать `Configure-Workspace.py --manager-email <email> --apply`; чужие
учётные записи не выбираются по догадке и не переназначаются.

Покупатели КИС 2 (ОАО «Каравай») и 3 (АО «ПАЛЯНИЦА»), одна точка 2 покупателя 2.
Имена, активность и принадлежность повторно проверяются живыми GET. Три адреса:
`demo.quick.point.<manager>@example.test`, `demo.quick.buyer.<manager>@example.test`,
`demo.quick.multi.<manager>@example.test`. Это тот же workflow/приватный план,
который подготовлен клиентским направлением; его snapshot и hashes — setup/SOURCE.json.
Других покупателей при отказе не подставлять. В КИС установка ничего не записывает.

Старые входы Install-Karavay-07.ps1 / Create-Demo-Users.py больше не запускают
самостоятельные demo.single/demo.multi. Для истории остаётся исходный выпуск
7dd630e4d891be71ddd7e7b19a553cd5f67258bf.

## Воспроизведение проверки

```bash
npm run check
node manager-live/tests/session.cjs
python3 manager-live/tests/installer.py
PB_BINARY=/path/to/pocketbase python3 manager-live/tests/integration.py
PB_BINARY=/path/to/pocketbase MANAGER_CHROME=/path/to/chrome-headless-shell python3 manager-live/tests/workspace.py
PWSH=/path/to/pwsh python3 manager-live/tests/powershell.py
python3 manager-live/scripts/build-release.py /path/to/output
```

Все PB/KIS данные этих тестов изолированы от рабочей VM. В браузере проверяется
настоящий текущий интерфейс, включая личный file:// вход и мобильный вид.
