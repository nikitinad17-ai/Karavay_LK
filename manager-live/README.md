# КАРАВАЙ — кабинет менеджера 0.9.0

Покупатель — организация, получатель — её торговая точка. Учётная запись из
`users` может иметь доступ ко всем точкам покупателя либо к отдельным получателям.
«Оформление заказов» и «Только просмотр» — возможности пользователя, а не тип точки.

[Разбор изменений, ограничения и установка](RELEASE_0.9.0.md).

## Новый набор демо

Две реальные компании из текущей КИС, минимум два активных получателя с адресами
у каждой. Для каждой компании создаются три самостоятельных входа:

| Пользователь | Доступ |
| --- | --- |
| Покупатель | Все его активные получатели |
| Получатель 1 | Только первая проверенная точка |
| Получатель 2 | Только вторая проверенная точка |

Всего шесть отдельных пользователей и шесть независимых паролей. Кнопки входа
находятся в `/manager/` → «Демо-пользователи». Каждый вход открывает обычный
клиентский кабинет в своей вкладке. Имена компаний/точек не придумываются.
Известные производители Каравай/Паляница и ранее отклонённые демо исключены.
При отсутствии двух подходящих компаний скрипт останавливается до записи.
История/каталог читаются клиентом отдельно; наличие заказов не является обещанием
этого набора. При настройке ни одного заказа не создаётся.

## Установка из Windows

Скачать готовый `Karavay-Manager-0.9.0-Recipients-20261027.ps1` в Downloads:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\Karavay-Manager-0.9.0-Recipients-20261027.ps1"
```

Нужен SSH/sudo VM, пароль админки PocketBase не требуется. Самодостаточный пакет
устанавливает менеджер, включает кнопку его тестового входа и настраивает шесть
демо. Успешный результат: `MANAGER_RELEASE_INSTALLED: 0.9.0`, затем
`RECIPIENT_DEMOS_READY: 6`. Браузер открывает серверную страницу менеджера.

Опции: `-PreflightOnly` — только проверка; `-TestLoginOnly` — менеджер и его
кнопка, без демо; `-ResumeSetup` — продолжение настройки установленного 0.9.0.
Повтор использует тот же набор ID, не сбрасывает пароли и не восстанавливает
вручную отключённые аккаунты/права. Не удалять сохранённый план ради повторного
подбора: сначала проверить причину остановки.

## Запуск в консоли VM

Из уже распакованного пакета, в терминале Ubuntu:

```bash
sudo python3 scripts/install.py --install
python3 scripts/Enable-Test-Login.py --enable
sudo python3 scripts/Setup-Recipient-Demos.py --apply
```

Без `--install`/`--apply` соответствующий шаг только проверяет состояние.
`Configure-Workspace.py --apply` сохранён как совместимое имя нового сценария.
Прежние приватные планы 0.8.x не используются и не изменяются.
Старые инструкции в RELEASE_0.8.0/0.8.1 являются историческими.

## Сохранность

Установщик проверяет PocketBase 0.40.3, действующую структуру и известные хэши,
делает резервные копии. Новая миграция демо добавляет данные в транзакции и не
меняет коллекции. Имеющаяся миграция `manager_owner` сохранена для более ранних
установок. Пароли обычных пользователей, клиентский HTML, gateway и отдельная
конфигурация клиентского `/service/test-access` не заменяются. Отдельные входы
не создают дубликатов получателей в КИС: используются её существующие точки.

Новые демо имеют случайные пароли, генерируемые внутри PB; в файлы исходные
пароли не сохраняются. `manager-recipient-demos.json` содержит ID/описания и
лежит только в `pb_data` с правами 0600. Новый вход доступен только действующему
назначенному менеджеру на шесть фиксированных демо, с проверкой всей области
доступа. Клиентские запросы проходят обычные `/service/*` проверки.

## Проверки разработчика

```bash
npm ci
npm run check
PB_BINARY=/path/to/pocketbase python3 manager-live/tests/integration.py
node manager-live/tests/session.cjs
python3 manager-live/tests/installer.py
PB_BINARY=/path/to/pocketbase python3 manager-live/tests/recipients.py
PB_BINARY=/path/to/pocketbase python3 manager-live/tests/workspace.py
PWSH=/path/to/pwsh python3 manager-live/tests/powershell.py
```

Для браузера: `MANAGER_CHROME=/path/to/chrome-headless-shell` и
`CLIENT_HTML=/path/to/current-built-client.html` при запуске `recipients.py`.
Используется настоящий локальный PB и текущий клиент 3.8, КИС/системная служба —
фикстуры. Внутренняя VM из этой среды недоступна; запуск на ней требует установки
оператором. Модель доступа и тему проверяют дополнительно к новым входам.

Сборка распространяемого пакета:

```bash
python3 manager-live/scripts/build-release.py /path/to/output
```
