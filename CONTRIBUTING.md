# Как работать с репозиторием

## Структура

```
app/                    исходники — их и правим
  index.html            точка входа для разработки (грузит файлы по отдельности)
  index.template.html   шаблон для сборки single-file
  app.js                UI: состояние, роутинг, рендер, адаптеры КИС
  api.js                демо-бэкенд: реализация методов КИС из ТЗ ver.2
  styles.css            стили
  products.js           номенклатура (111 SKU) в window.__PRODUCTS__
  favicon.svg
  docs/                 PDF-документы, доступные из раздела «Документы»
shared/                 логотипы
tests/t2.js             автотест на Playwright (29 проверок)
build_inline.py         сборка всех файлов в один HTML
index.html              собранный файл — то, что открывают и публикуют
products.json           исходные данные номенклатуры
docs-project/           аналитика по проекту
```

## Правило номер один

Правим **только то, что в `app/`**. Файл `index.html` в корне — результат
сборки, руками его менять нельзя: правки затрутся при следующем запуске
`build_inline.py`.

## Сборка

```bash
cd app
python3 ../build_inline.py     # создаёт app/standalone.html
cp standalone.html ../index.html
```

`app/standalone.html` в git не попадает (см. `.gitignore`) — публикуемым
считается `index.html` в корне.

## Тесты

```bash
npm install -D playwright
npx playwright install chromium
node tests/t2.js
```

29 проверок: загрузка по API КИС, группы ЗПФ/ХБИ, ограничение дат по дням
недели, создание заказа, правка через PATCH, разграничение ролей.

Тест открывает `app/standalone.html` через `file://`, поэтому перед запуском
нужна сборка. В окружении без доступа в сеть в консоли появится 403 на
Google Fonts — это ожидаемо и на результат не влияет.

## Ветки и версии

- `main` — стабильная версия
- Версия фиксируется тегом: `v2.0`, `v2.1` и так далее
- Историю версий ведём в `README.md`, раздел «История версий»

## Перед коммитом

1. `node --check app/app.js && node --check app/api.js`
2. Пересобрать и прогнать `node tests/t2.js`
3. Обновить `README.md`, если поменялось поведение

## Чего в репозитории быть не должно

Настоящих паролей, токенов, ключей API и персональных данных клиентов.
Демо-пароли в `api.js` — вымышленные и существуют только для показа; при
переходе на реальную аутентификацию их нужно удалить целиком, а не заменить.
