# Разработка

## Перед изменениями

1. Прочитайте `PROJECT_CONTEXT.md` и `readmegpt.md`.
2. Установите зависимости через `npm ci`.
3. Не меняйте иерархию покупатель → получатели и контракт API без отдельного решения.

## Проверка

```bash
npm run check
npx playwright install chromium
npm run test:e2e
```

`npm run check` последовательно выполняет строгий `tsc --noEmit`, Vitest и production-сборку. Не обходите ошибки через `any`, `@ts-ignore` или `@ts-nocheck`.

Новая бизнес-логика должна иметь unit-тест. Пользовательский сценарий — интеграционный или E2E-тест. Исправление гонки должно воспроизводить порядок ответов, а не зависеть от случайной задержки.

## Коммиты

- один логический результат на коммит;
- не коммитить `node_modules/` и `dist/`;
- обновлять документацию при изменении запуска, адресов, контрактов или этапов развития;
- не добавлять секреты, реальные токены и персональные данные.
