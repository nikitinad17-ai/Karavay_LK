# КАРАВАЙ — последние изменения

**Дата:** 28 октября 2026 года.

**Версия функций:** Classic 3.8.5.

**Последнее обновление:** яркое оформление от 28.10.2026 без изменения логики.

Документ фиксирует подготовленные изменения и результаты проверок. Установка последних пакетов на VM и конкретные выбранные покупатели/получатели ещё требуют подтверждения результатом запуска.

## 1. Оформление — 28.10.2026

По просьбе владельца возвращён более яркий стиль старых версий:

- насыщенная синяя боковая панель и синее приветствие;
- жёлтые основные кнопки и активные пункты меню;
- шрифт Ubuntu с кириллицей, включённый в пакет;
- более выразительные карточки, поля, таблицы и диалоги;
- адаптация для телефона и средней ширины экрана;
- панель итогов под каталогом на средней ширине, чтобы названия товаров оставались читаемыми.

**В этом обновлении изменены только стили и шрифты.** Сохранены шесть разделов, вход, права, демо-сценарии, история, повтор заказа и правила расчёта количества.

Установщик добавляет CSS в имеющийся HTML. Скрипты приложения сохраняются побайтно. Предусмотрены проверка исходного файла, резервная копия и откат при ошибке или прерывании. База данных, пользователи, права и менеджер не меняются; перезапуск PocketBase не требуется.

**Пакет:** `Karavay-Style-Bright-20261028.ps1`.

**Успешный результат:** `BRIGHT_STYLE_READY` или `BRIGHT_STYLE_ALREADY_OK`, затем обновление страницы через **Ctrl+F5**.

## 2. История и повтор заказа — 3.8.5

- Из таблицы и карточки убран «Статус КИС».
- Вся строка истории открывает заказ мышью или клавишами Enter/Space.
- Справа от каждого заказа добавлена кнопка «Повторить заказ».
- Такая же кнопка доступна внутри карточки заказа.

Прежний «Статус КИС» был прямым выводом служебного поля `state`. На снимке встречались значения `7.5` и `8`; подтверждённой расшифровки их бизнес-смысла нет.

При повторе выбираются дата и группа продукции. Состав сопоставляется по точному коду товара с актуальным прайсом. Цена, идентификатор позиции, укладка и ограничения берутся из нового прайса, общее количество штук сохраняется.

Недоступные товары, отсутствие цены, неоднозначные коды и неизвестная укладка показываются явно. Частичный перенос требует отдельного действия, замена непустой корзины — подтверждения. Отмена, ошибка или запоздалый ответ не стирают текущую корзину.

**Повтор заполняет корзину. Заказ отправляется только после обычной проверки и подтверждения пользователем.**

## 3. Демо-пользователи: разные сценарии

Подготовлены три входа без ввода пароля. Вымышлены только email; покупатели и получатели выбираются из тестовой КИС.

| Демо-вход | Доступ |
| --- | --- |
| `demo.test.point.v385@example.test` | Один получатель покупателя A |
| `demo.test.buyer.v385@example.test` | Все активные получатели покупателя B; обязательно минимум два разных |
| `demo.test.multi.v385@example.test` | Покупатели C и B со всеми их активными получателями |

A, B и C — обозначения трёх выбираемых покупателей, а не их названия.

Для второго входа наличие минимум двух получателей проверяется через защищённый маршрут кабинета. На кнопке «Несколько получателей (от 2)» показываются названия и коды двух проверенных точек. Успех объявляется только после проверки входов и областей доступа.

Каравай и Паляница исключены из подбора как производители. Текущие демо-покупатели также исключаются. При отсутствии подходящих данных фиктивные покупатели и точки не подставляются.

Создание входов больше не зависит от исправности прайса или непустой истории. После создания отдельно читается реальная история двух проверенных получателей. Пустая история и ошибки показываются честно; заказы, цены и история не генерируются.

**Пакет:** `Karavay-Orders-3.8.5.ps1`.

**Подтверждение нескольких получателей:** `MULTI_RECIPIENT_DEMO_READY` с количеством не меньше 2, затем `SCENARIOS_READY`.

Существующие пользователи, их пароли, права и менеджер сохраняются. Конкретные новые названия покупателей и получателей пока не подтверждены выводом VM.

## 4. Дата и количество

Для тестового входа устаревшая сохранённая дата заменяется на завтра по Москве.

Ранее принятые правила лотков и штук сохранены:

- общее количество штук = лотки × укладка + отдельные штуки;
- цена применяется к общему количеству штук;
- пустое или отсутствующее `KolshtOrdmin` означает заказ только целыми лотками;
- явный ноль отличается от пустого значения и допускает отдельные штуки;
- при неизвестной укладке товар, доступный только лотками, блокируется;
- недопустимое количество при повторе не округляется автоматически.

Локальные тестовые ответы не доказывают работу реальной КИС. Нативный запуск PowerShell-установщиков и применение последнего оформления на VM в этой среде не проверялись.

## 6. Что остаётся открытым

- **Создание заказа:** ранее КИС вернула HTTP 400, `Не задан aId_Clt`, код `-20001`. Разбор поставлен владельцем на паузу; исправление не входит в эти пакеты.
- **Прайс:** владелец подтверждал ошибку и на актуальную дату. Точный новый ответ КИС пока неизвестен; смена даты сама по себе не подтверждает исправление.
- **История:** на снимке владельца отображались заказы №6408, №8327 и №105. Это подтверждает непустую историю в показанном контексте, но не наличие заказов у каждого нового демо-получателя.
- **VM:** нужен фактический результат установки, чтобы подтвердить новое оформление и назвать выбранных покупателей/получателей.

## 7. Порядок дальнейшей работы

Если функции текущего кабинета работают, для изменения внешнего вида использовать только `Karavay-Style-Bright-20261028.ps1`. Повторная установка демо ради оформления не требуется.

После успешного результата и Ctrl+F5 проверить внешний вид, переключение получателей, открытие истории и перенос заказа в корзину. Дальнейшие изменения логики — только по отдельной задаче владельца.
