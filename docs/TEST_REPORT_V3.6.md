## Покрытие новой модели доступа

Автоматизированы проверки:

1. один доступный покупатель выбирается автоматически;
2. несколько покупателей требуют отдельного экрана выбора;
3. для выбранного покупателя запрашиваются только его активные получатели;
4. отсутствие связей возвращает `NO_BUYER_ACCESS`;
5. неактивный пользователь не входит;
6. неактивная связь `user_buyers` не даёт доступ;
7. чужой покупатель отклоняется до API-запроса, а точка с чужой relation блокируется fail-closed;
8. восстановление после F5 обновляет users-сессию и заново проверяет доступный каталог;
9. выход очищает токен и выбранного покупателя из `sessionStorage`;
10. request gate не применяет устаревший ответ быстрого переключения;
11. корзина и несохранённые корректировки требуют подтверждения перед сменой юрлица;
12. сброс контекста очищает корзину, заказы, документы, правки и кэши предыдущего покупателя.
